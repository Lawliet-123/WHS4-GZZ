# Shared 0.1.0 검증 기록

검증일: 2026-09-27. 환경: Windows / Python 3.14.6. 실제 중앙 서버 및 실제 게임을 실행한 테스트가 아니다.

## 실행 결과

| 검사 | 결과 |
| --- | --- |
| shared 전용 단위·계약·로컬 HTTP·동시성 테스트 | 39개 통과 |
| 기존 AutoPaint/Lua mock을 포함한 전체 회귀 테스트 | 97개 통과 |
| loopback 데모 | PASS; HTTP 요청 3회, 고유 Event 2건 저장, pending/failed 0 |
| Python 3.10 문법 검사 | shared 소스 전부 통과; 3.10 런타임 실행 검증은 아님 |
| 기존 0.3.0 ZIP과 현재 AutoPaint Python/Lua 소스 비교 | 비교한 15개 파일 변경 없음 |

전체 회귀 테스트의 첫 일반 실행은 기존 `.test-deps/lupa` 읽기 권한 때문에 Lua 테스트 로딩이 실패했다. 권한이 허용된 실행에서 전체 97개가 통과했다. 기존 테스트 코드를 수정해서 오류를 우회하지 않았다.

## 신규 테스트가 확인한 내용

- 기존 7필드 유지, 0점·원래 timestamp 보존, 유효하지 않은 JSON·자료형·경로 거절
- import만으로 파일·네트워크·스레드를 생성하지 않음
- 로컬 HTTP 전송, 401/422 중단, 429/503 재시도, redirect 차단
- 잘못된 수신 확인 응답과 timeout을 성공으로 처리하지 않음
- 인증서 검증 실패 처리 경로: 모사 예외 테스트이며 실제 외부 TLS 연결 테스트는 아님
- 저장 성공 후 응답 유실 시 같은 ID로 재시도하고 JSONL에는 한 번 기록
- 미전송 pending의 재시작 복구, failed 보존·수동 재시도·접근 키 교체
- 대기열 건수·payload 용량 제한, 디스크 실패 노출, 호출 이후 입력 dict 변경의 영향 차단
- 멀티스레드 발행, 복수 프로세스 저장, 동일 outbox의 두 sender 방지
- 서버 기록 전/도중/후 중단을 모사한 recovery 및 외부 파일 변경 시 fail-closed

## 기존 제출 로그 형식 호환

| 원본 ZIP | 검증한 Event |
| --- | --- |
| normal_host_demo_0923_001.zip | 110개 |
| autopaint_host_demo_0923_004.zip | 162개 |

272개 모두 shared의 검증·직렬화·역직렬화를 통과했고 원래 dict 값과 동일했다. ZIP의 검사 전후 SHA-256도 동일했다. 이 검사는 형식 호환 검사이며 해당 플레이 로그를 서버에 전송하거나 다시 테스트한 것이 아니다. 원본 ZIP과 원본 로그는 인수인계 ZIP에 넣지 않는다.

## 아직 확인하지 않은 범위

- 실제 팀 receiver의 인증·응답·player/session 소유권 처리
- 실제 중앙 scoring 및 Dashboard 연결
- 외부 HTTPS 운영 서버와 클라우드 지속성·분산 중복 관리
- 장시간 장애·대규모 동시접속·운영 수준 성능
- 실제 전원 차단, 디스크 손상, 악성 로컬 파일 변조에 대한 복구 보장
- 다른 OS와 Python 3.10~3.13 런타임 실행

라이브러리와 규약을 전달한 뒤 실제 서버 담당 A/B와 동일 계약의 통합 검증이 필요하다.
