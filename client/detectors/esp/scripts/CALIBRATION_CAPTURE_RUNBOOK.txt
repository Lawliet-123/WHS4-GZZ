ESP calibration 자료 수집 준비 / 2026-10-07

구현·자동화 검증 기준 상태 (실제 수집 결과와 별도)

이 문서의 자동화 시험은 새 NORMAL / ESP ON 실게임 수집 완료를 뜻하지 않는다.
최초 준비 확인 시 게임 미실행, Sysmon 서비스 없음, 작업 프로세스 비관리자였다.
이 문서나 합성 입력 테스트를 실게임 완료 자료로 제출하면 안 된다.
기존 Replay는 중앙 전송이 꺼져 있었고 remote player 0명도 읽기 성공으로
인정했으므로, 새 Server -> Scoring calibration 자료를 대신할 수 없다.

이번에 보완한 부분

1. realgame_replay.py에 --server-setup 선택 옵션을 추가했다.
   realgame_server가 만든 빈 loopback 서버의 setup.json만 받는다.
   production 환경변수, 접속키, 기존 데이터베이스는 사용하지 않는다.
   warmup은 중앙에 보내지 않고 본 세션의 기존 Shared 7필드 Event만 보낸다.
2. queued와 HTTP ACK를 구분한다. pending / failed가 0이고 ACK 수가 맞아야
   다음 단계로 간다. 실제 Server Event UUID, sequence, UTC 수신 시각,
   목록/상세 7필드, Scoring snapshot / Final Verdict를 서로 비교해 저장한다.
3. NORMAL Event 0건도 허용한다. 없는 raw 0 Event를 합성하지 않는다.
   데이터가 없으면 UNKNOWN / verdict 404 / null을 그대로 남긴다.
4. 프로그램 spawn, 실제 게임 handle ON, 첫 local read, 다른 플레이어의
   실제 box / skeleton draw, process OFF를 따로 기록한다.
   중앙 연동 positive는 서로 다른 fresh frame에서 remote geometry를
   실제로 그린 관측이 최소 2개 있어야 한다. 프로그램 실행만으로는 안 된다.
5. 세션 시작/종료 UTC와 t0 기준 ms, OFF 후 정확히 소유한 자식의 종료 여부,
   게임의 loaded-module snapshot 전후 지문 차이를 추가했다.
6. 자료는 private staging에서 완성한 뒤 새 Replay 디렉터리로 publish한다.
   부분 생성이나 기존 세션 덮어쓰기를 성공 결과로 내보내지 않는다.
   실패한 lifecycle proof는 failed로 기록하고 raw/outbox는 로컬에 남긴다.
7. Windows venv의 중간 실행기를 피하면서 venv 패키지는 유지한다.
   Popen PID와 실제 Python PID가 일치하는 stdlib-only probe도 통과했다.
8. production의 PID + 생성 시각 기반 Launcher 제외 정책은 그대로 사용한다.
   Scoring 정책, threshold, Receiver, Shared 규격, 프론트는 바꾸지 않았다.
9. 2026-10-07 main c782c2e의 observed_at_utc 조회 메타데이터를 지원한다.
   목록/상세의 기준은 기존 DashboardIndex.event_clock projector와 대조한다.
   선언 충돌은 unknown, 잘못된 기준시각은 관측 시각 미제공으로 보존한다.
   null 수신 시각을 관측 시각으로 채우지 않고 수신 메타데이터 완전성도 따로 남긴다.
   유효 관측 시각은 UTC ISO 8601과 밀리초 및 실제 선언의 계산 결과를 검증한다.
10. CREATE_NO_WINDOW worker의 출력은 PIPE로 수집하고 고정 JSON 진단만 전달한다.
    센서 상태, 경과/예산, 오류 종류/단계, 종료코드는 보이지만 원본 stderr,
    traceback, reason 문자열, 경로, 사용자명, 접속값은 전달하지 않는다.
11. 첫 warmup은 기존 Sysmon Event 10의 RecordID만 prime한다. 세션 시작 이전
    backlog를 다시 서명·점수 분석하지 않고 기존 production poller의
    include_existing=False 기능을 사용한다. 이후 신규 레코드는 정상 수집한다.
    warmup의 truncated/실패는 부족으로 유지하고 본 세션에는 건강한 poll
    2회 확인 후에만 진입한다. 기본 warmup 90초, --warmup-timeout 최대 180초다.
    본 수집 duration이나 실제 ESP 준비/remote draw 기준은 완화하지 않았다.
12. 소유 collector와 sender가 성공적으로 닫힌 뒤에만 publish한다. 성공한
    close를 finally에서 다시 호출하지 않고, 실패한 close만 정리 단계에서
    재시도한다. cleanup 실패를 완료 Replay로 승격하지 않는다.
13. production Sysmon poller의 EvtNext에서만 ERROR_NO_MORE_ITEMS(259)를
    정상 열거 종료로 처리하고 이미 읽은 기록을 보존한다. 같은 코드가
    query/render/channel에서 나오거나 다른 EvtNext 오류면 계속 unavailable이다.
    scan cap에 따른 truncated도 그대로 남는다. 모의 API 재현과 Microsoft
    계약에 따른 일반 버그 수정이며, 이번 실게임 warmup 실패가 실제 259
    때문이었다고 확정하지 않는다. 실제 native probe를 실행한 검증도 아니다.
    근거: https://learn.microsoft.com/en-us/windows/win32/api/winevt/nf-winevt-evtnext
14. 원본 ESP의 초기화 시작/완료와 overlay 준비를 별도 고정 단계로 표시한다.
    초당 readiness 진단은 camera 존재, local/remote player 수, 신선도,
    collection 상태 등 scalar와 허용된 enum만 전달한다. 예외 본문·주소·
    사용자명·경로는 제외하며 이 진단만으로 ON/remote draw를 인정하지 않는다.
    실제 준비는 기존 verified_frame와 완료된 원본 painter 호출로만 판단한다.
    초기화가 느린 게임에서는 제한된 --readiness-timeout 120과 전체 duration
    210을 사용한다. 실제 ESP 60초 동작과 센서 정상 검증 조건은 그대로다.

실제 수집 전 준비

승인된 비공개 테스트방에서 캐릭터를 조작할 수 있고 다른 플레이어를 볼 수
있어야 한다. NORMAL에서는 기존 PoC를 모두 꺼야 한다. 이 도구는 다른
프로그램을 임의로 종료하지 않으며 기존 PoC 전체 부재를 자동 입증하지 않는다.
관리자 PowerShell과 실행 중인 Sysmon 및 Event 10 수집 정책이 필요하다.
이 수집 도구는 Sysmon 설치, Windows 기능 활성화, 권한 상승을 자동 수행하지 않는다.
아래 명령은 이 조건을 갖춘 뒤 실행한다. 한 세션을 마치고 다음을 실행한다.

PowerShell 1: 새 local C 서버 (기존 서버/저장소에 연결하지 않음)

cd "C:\Users\nojiw\Downloads\WHS4-GZZ-esp-calibration-oct7"
$espCalibrationPython = "C:\Users\nojiw\Downloads\WHS4-GZZ-realgame-e2e\.venv-esp-calibration\Scripts\python.exe"
& $espCalibrationPython -B -m server.dashboard_backend.realgame_server serve --port 8002 --duration 900 --output .\logs\esp-calibration-server-20261007-run01

output은 새 디렉터리여야 한다. 이미 쓰인 경로라면 run02처럼 새 이름을 쓴다.
서버가 출력한 setup_path를 아래 --server-setup에 넣는다. 토큰을 소스에 넣지 않는다.

관리자 PowerShell 2: 준비 확인과 NORMAL

cd "C:\Users\nojiw\Downloads\WHS4-GZZ-esp-calibration-oct7"
$espCalibrationPython = "C:\Users\nojiw\Downloads\WHS4-GZZ-realgame-e2e\.venv-esp-calibration\Scripts\python.exe"
$espCalibrationGamePid = (Get-Process -Name 'PenguinHotel-Win64-Shipping' -ErrorAction Stop).Id
Get-Service -Name Sysmon,Sysmon64 -ErrorAction SilentlyContinue | Select-Object Name,Status
& $espCalibrationPython -B .\client\detectors\esp\scripts\realgame_replay.py --approved-private-test-room --scenario normal --game-pid $espCalibrationGamePid --duration 120 --player-id calibration_player --session-id normal_calibration_20261007_run01 --server-setup .\logs\esp-calibration-server-20261007-run01\setup.json

NORMAL 종료 및 PoC 부재를 확인한 뒤 별도 ESP 세션

& $espCalibrationPython -B .\client\detectors\esp\scripts\realgame_replay.py --approved-private-test-room --scenario esp --game-pid $espCalibrationGamePid --duration 210 --esp-seconds 60 --readiness-timeout 120 --player-id calibration_player --session-id esp_calibration_20261007_run01 --server-setup .\logs\esp-calibration-server-20261007-run01\setup.json

ESP 세션은 이 도구가 원본 ESP를 소유한 자식으로 실행하고 종료한다.
ESP를 별도로 한 번 더 실행하지 않는다. 게임 재시작 시 이전 PID를 재사용하지 않는다.
관측 부족, remote geometry 없음, 강제 종료, 미전송/실패/Server 불일치는
성공한 Replay로 내보내지 않는다. 결과를 임의로 CHEAT / NORMAL로 바꾸지 않는다.

성공 후 전달 자료

ReplayAnalyzer/replay-data/esp/<session_id>/manifest.json
ReplayAnalyzer/replay-data/esp/<session_id>/events.jsonl
ReplayAnalyzer/replay-data/esp/<session_id>/calibration-evidence.json

manifest의 source.calibration_observation에는 세션 UTC, 프로그램 실행 구간,
handle ON/OFF, 실제 remote draw 첫/마지막 관측 구간, 잔존 관측, ACK 요약,
Server 자료 해시가 들어간다. Server 자료에는 실제 저장 Event와 Scoring 응답이 있다.
로컬 data/realgame_capture의 raw, sqlite, profile, setup 인증값은 올리지 않는다.
중앙 Event의 source_pid/window_pid는 실제 Event와 맞는 세션 상관관계 값이다.
사용자명, 컴퓨터명, 창 제목, 전체 경로, 토큰은 public readback에서 거부한다.

보고할 때 구분할 점

remote painter 호출 관측은 원본 ESP의 기능 관측이며 스크린샷/사람의 인지를
검증한 것은 아니다. 첫/마지막 관측 경계는 연속 표시나 사용자 행동 구간을
자동 보장하지 않는다. 직접 조작한 행동 시각은 별도로 적고 미관측이면 null이다.
module snapshot 차이는 로드된 모듈 목록의 변화이며 ESP 주입의 인과관계나
디스크 DLL 무결성까지 입증하지 않는다. 실패하면 UNKNOWN으로 남긴다.
소유한 자식 외의 다른 프로세스와 기존 DLL은 정리 대상이 아니다.
Server evidence는 local C 앱의 실제 stores/API에 대한 자료이지 공개 Vercel
프론트나 운영 HTTPS 서버 검증 자료가 아니다. stores 정리 전 readback을 보존한다.
realgame_server 종료 summary의 Launcher heartbeat 검사는 별도 범위다.
ESP-only capture를 Launcher 전체 모듈 E2E 완료로 해석하면 안 된다.
현재 ESP calibration의 pending 판정은 임의 threshold로 바꾸지 않는다.

LocalGuard YARA

localguard_yara는 input_signature 탐지기다. 내가 만든 DLL 무결성의
external_access / evidence.submodule=module_integrity와 다르다.
YARA NORMAL / production ruleset 실제 positive는 이번 작업에서 수집하지 않았다.
기본 ruleset 사용 시 --rules를 지정하면 custom_cli가 되어 advisory이므로
동일 파일이라고 임의 옵션을 붙이지 않는다. ruleset identity/engine/scope와
실제 Server 저장 및 Scoring 결과를 별도로 확보해야 한다.
DLL 테스트나 YARA test-only fixture를 production positive로 제출하지 않는다.
