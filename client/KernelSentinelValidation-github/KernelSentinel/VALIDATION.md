# 검증 상태와 VM 인수 검사

**0.2 추가 검증:** `PATCH_v0.2.md` 및 `TEST_RESULTS.txt` 참조. 아래는 초기 0.1 작성 당시 기록입니다. 이후 사용자 VM에서 캐시 패치 버전의 로드와 정상 해시 비교는 확인됐지만, 새 0.2 SYS의 Windows 검증은 별도로 필요합니다.

## 작성 환경에서 완료한 검증

2026-09-23 Linux, Python 3.12 및 GCC에서 오프라인 자동 테스트 17개를 수행했습니다.

- 64비트 주소·UTF-16 경로·Windows 절대 시각 역직렬화.
- 잘못된 이벤트 크기, 버전, 모듈 개수 거부.
- 코드 스캔 결과 구조 352바이트, 이벤트 616바이트, 상태 48바이트, 정책 24바이트.
- C 권한 제한 정책의 모드/heartbeat/커널 핸들/자기 접근 조합, 쓰기 권한 제거와 읽기/조회 보존.
- 핸들 요청 실패와 실제 부여를 구분, pre/post 중복 점수 억제.
- 이름/해시 규칙, 서명 불명과 읽기 실패에 악성 점수를 부여하지 않음.
- 교차 조회의 3회 지속 조건, 로드/언로드 중간 변화와 권한 문제의 오탐 억제.
- 원시/공통 로그 분리, 공통 이벤트 중복 억제, 기존 출력 폴더 덮어쓰기 거부.

이 검사는 kernel API 실행을 에뮬레이션하지 않습니다. Windows WDK 컴파일, INF/서명 통과, 실제 드라이버 로드와 콜백 동작, SHA-256 커널 스캔 런타임, 성능·동시성·게임 호환성은 **미검증**입니다.

## 실제 샘플 평가 시 기록할 것

각 세션마다 OS 빌드, SYS SHA-256, 모드, 게임 실행파일, 보호 시작 시각, 샘플 시작/종료 시각을 기록합니다. 정상 세션과 샘플 세션을 나누고 원시 JSONL 전체를 보존합니다.

커널 코드 변조 평가에는 어떤 모듈의 어떤 범위가 언제 변경됐는지 별도 디버거/덤프 관찰 결과가 필요합니다. 첫 기준 전에 이미 변조된 코드, 모듈 재방문 전 원상복구된 코드, 검사 제외/실패 섹션은 놓칠 수 있습니다. 변경 이벤트가 없다는 사실만으로 미변조라고 판정하지 않습니다.

은닉 평가에는 동일 조회 API만 다시 호출하는 확인으로는 충분하지 않습니다. 독립적인 메모리 덤프/디버거 등으로 대상의 존재를 확인하고, 조회 목록과 불일치하는 원인을 따로 분류해야 합니다. 이 구현의 두 목록이 동시에 속는 경우는 검출 불가능 사례로 보고합니다.

보고서에는 `탐지 성공`, `검사했으나 미탐`, `관측 범위 밖`, `검사 실패`, `정상 변경/오탐`을 구분합니다. 테스트용 이름 규칙이나 합성 로그 테스트의 통과를 실제 커널 치트 탐지 성공으로 집계하지 않습니다.
