# Dashboard 화면 설계

## 목적

이 화면은 운영자가 다음 순서로 확인하도록 만든다.

1. Receiver, Scoring, Launcher가 조회 가능한가
2. 어떤 세션과 플레이어에 판정이 있는가
3. 어떤 모듈과 Event가 판정 근거가 되었는가
4. 원본 reasons와 evidence는 무엇인가

사용자가 처음 봐도 데이터 흐름을 이해할 수 있도록 `시스템 상태 → 대상 선택 → 최종 판정 → 모듈 상태 → Event 상세` 순서로 배치한다.

## 정보 구조

```text
┌──────────┬────────────────────────────────────────────┐
│ MECCHA   │ 탐지 현황                 DEMO/LIVE · 연결 │
│          ├────────────────────────────────────────────┤
│ 현황     │ Receiver · Scoring · Launcher             │
│ 대상     ├────────────────────────────────────────────┤
│ 이벤트   │ 검색 · 세션 · 플레이어 · 모듈 · 판정     │
│ 시스템   ├────────────────────────────────────────────┤
│          │ 세션 · 플레이어 · 이벤트 · 의심 판정     │
│          ├───────────┬──────────────────┬─────────────┤
│          │ 대상 목록 │ 최종 판정        │ 모듈 상태   │
│          ├───────────┴──────────────────┴─────────────┤
│          │ 최근 흐름                 │ 실행 상태   │
│          ├────────────────────────────────────────────┤
│          │ Event 표 → 우측 상세 drawer               │
└──────────┴────────────────────────────────────────────┘
```

큰 소개 문구, 영문 장식 제목, 반복 안내 박스와 판정 면책 문구는 화면에서 제거했다. 데이터 이름, 상태, 수치와 조작 요소만 남긴다. 합성 데이터는 상단의 `DEMO` 배지 하나로 구분한다.

## 판정과 점수

| 값 | 화면 표시 |
| --- | --- |
| `SUSPICIOUS` | 의심 근거 있음 |
| `INCONCLUSIVE` | 판단 보류 |
| `NO_ACTIVE_EVIDENCE` | 활성 근거 없음 |
| `UNKNOWN` | 판정 없음 |

Scoring의 최종 판정은 변경하지 않는다. `UNKNOWN`과 데이터 없음은 정상 판정으로 보이지 않게 분리한다. 각 모듈의 `raw_score`는 Event와 모듈 카드 안에서만 보여 주며 합산하지 않는다. `score`와 `confidence`가 없는 현재 계약에서는 숫자 위험도를 만들지 않는다.

## 상태

- 상단 연결 바: `overview.connection`
- 선택 대상 실행 상태: `/status`의 `launcher`와 component
- 동기화 상태: `overview.index.catching_up`
- 마지막 화면 시각: 브라우저의 API 조회 완료 시각
- Event 시각: `timestamp_ms`를 세션 경과시간으로만 표시

Receiver와 Scoring의 `online`은 각각 서버 로컬 저장소·읽기 계층의 준비 상태다. 전체 원격 센서가 정상이라는 의미로 확대하지 않는다.

## 상호작용

- 필터는 대상 목록과 Event 표에 함께 적용된다.
- 대상 선택 시 `/snapshot`과 `/status`를 동시에 조회한다.
- Event 행이나 최근 흐름을 누르면 `/events/{event_id}` 상세를 연다.
- 상세 drawer는 공통 7필드와 backend metadata를 분리해 보여 준다.
- 실서버는 5초마다 마지막 `sequence` 이후 Event를 증분 조회한다.
- API 오류 시 현재 자료를 유지하고 오류를 표시하며 demo로 자동 전환하지 않는다.

## 반응형

- 1280px 이하: 모듈 상태를 대상·판정 아래 가로 카드로 이동
- 980px 이하: sidebar 축소, 2열 요약
- 760px 이하: sidebar drawer, 대상·판정 1열
- 560px 이하: 필터 1열, Event 표 카드 전환

색상만으로 상태를 구분하지 않고 아이콘과 문구를 함께 사용한다. 조작 요소에는 focus 상태와 접근 가능한 이름을 둔다.
